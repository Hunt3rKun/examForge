# Exam IR — current-state contract

## Implemented

- `schemas/exam-ir-v1.json`: exchange schema for exam metadata, globally unique assets, ordered `sections[]`, normalized bounding boxes, content blocks, recursive question items, provenance, and an optional top-level `warnings[]` (bounded parser/processing observations, ≤128 entries of ≤512 chars; exchange metadata only — persistence does not store it). Every section has a unique-in-exam `section_id`, non-empty `title`, optional `instruction`, and at least one `questions[]` entry. Question occurrences may carry an optional `question_id`; recursive `children[]` remain within their parent question. It bounds strings (`maxLength`), arrays (`maxItems`), assets/tables/question fan-out, table spans, and option labels (`minLength: 1`). Exam `metadata.title`/`subtitle` and section `title`/`instruction` are tokenized through the same inline parser as other inline text fields.
- `schemas/layout-spec-v1.json`: independent renderer layout options.
- `internal/ir/`: typed DTOs plus `Validator`, which compiles both schemas once, validates and decodes the same bytes (`DecodeExamIR`/`DecodeLayoutSpec`), and enforces semantic limits JSON Schema cannot express: 8 MiB Exam IR, non-empty and unique section IDs, non-empty section titles and question lists, cross-section asset references resolved through the exam-level `assets` map, question depth 4, 8192 questions, table columns 64 / rows 512 / cell slots 8192, `assets` key equals `asset_id`, option labels are non-empty plain text, and each question's `{{blank:N}}` numbering is unique and contiguous from 1. `Table.Headers` is typed `TableHeaders` and normalizes flat or nested exchange shapes at decode time. `ValidateExamSemantics` is also called by `Precompile`, so library callers cannot bypass bounds.
- `internal/ir/inline/`: deterministic Go inline tokenizer (MVP slice 1). `inline.Parse(source)` returns `Result{Tokens, Diagnostics}` for the supported inline subset: plain text, `$LaTeX$` (`math_inline`, raw LaTeX payload), `**bold**`, `*italic*`, `__underline__`, and `{{blank:N}}` (1-based index). Escapes (`\\`, `\$`, `\*`, `\_`) are honored; malformed markup degrades to literal text with a `Diagnostic` (code + byte range), never a panic or silent drop. Unsupported constructs stay literal. Style segments split by inline math never emit empty tokens. Table-driven tests: `internal/ir/inline/inline_test.go`.
- `cmd/ircheck/`: schema-validation CLI used by the verify gate.
- `internal/ir/validate.go` `Validator.ValidateExamDTO`: validates a typed `ExamDocumentIR` by value (schema + semantics, input never mutated) for callers that already decoded it, such as the ingest worker and the assembler.
- `testdata/golden/ir/sample.json`, `testdata/golden/layout/student.json`, `testdata/golden/layout/teacher.json`: golden exchange fixtures.
- `testdata/render/ir/` (`options.json`, `pages.json`) and `testdata/render/layouts/*.json`: render fixtures exercising option-grid measurement, paper sizes, binding line, header/footer, floats, tables, blanks, and answer-space reserves.

`ExamDocumentIR` is an exchange/render-view DTO, not a database model. Its ordered `sections` are the only top-level question grouping; questions are nested under each section, while `question_id` is an optional occurrence identifier (not a persistence key contract). Question asset references at any nesting depth resolve against the document-wide `assets` map.

Slice 2 implements persistence behind the DTO (`internal/store`, migrations `0001`–`0005`; see `docs/subsystems/pipeline-queue.md`): global `assets` keyed by unique `asset_id`, reusable `questions` entities, and `exams`/`exam_sections`/`exam_items` for occurrence ordering. `Assembler.Persist` splits a document into those tables; `Assembler.Assemble` rebuilds an equivalent `ExamDocumentIR` whose `question_id` values are entity UUIDs, per-item `display_number`/`score` are occurrence overrides, and asset `uri` values are `examforge-asset://<asset_id>` locators rather than paths or object keys. The DTO must not mirror the tables.

Slice 3 adds source-document asset constraints on top of the unchanged v1 asset shape (`internal/parser/cloud` bbox validation, not the JSON Schema): every model-produced asset must carry a `source_bbox` with finite, correctly ordered corner coordinates in [0,1] whose `page` exists in the rasterized source. The schema itself still cannot bound `page` by the actual document; that check lives in the parser and runs before any crop.

## Change rule

Schemas are authoritative and must be updated first when changing data shape. Keep this contract synchronized with actual schema, Go, and fixture paths. Inline parsing lives only in Go `internal/ir/inline`; Typst templates consume precomputed tokens and must never re-parse inline markup. Rendering consumes the IR through `internal/render` — see `docs/subsystems/render-engine.md`.
